
Yes. The key is to separate physical material length, sampling/indexing, and geometry shape. They are related, but not the same thing.

1. Are we moving from 0 mm to 6500 mm with wrappedLength?

Yes.

Think of the original straight pipe as having a material coordinate s:

Original pipe material coordinate


s = 0 mm                                      s = 6500 mm
|------------------------------------------------------|
^                                                      ^
start                                                  end

During manufacturing, wrappedLength tells us how much of those 6500 mm has already passed through the forming point and become formed material.

For example:

wrappedLength = 2000 mm

|==========================|-----------------------------|
       FORMED                     INCOMING
       2000 mm                    4500 mm

Later:

wrappedLength = 5000 mm


0                                             5000    6500
|===============================================|-------|
                    FORMED                       incoming
                                                 ^

Finally:

wrappedLength = 6500 mm


0                                                     6500
|======================================================|
                         FORMED
                                                       ^
                                                wrappedLength

So yes: wrappedLength progresses from 0 → 6500 mm.

2. Why doesn't wrappedLength grow in equal sections?

Because your simulation timestep dt is not always equal.

Approximately:

deltaLength =
    centerlineSpeed * dt;

Your speed is approximately:

centerlineSpeed = 1020.2 mm/s

Therefore if:

dt = 0.100 s

then:

deltaLength ≈ 1020.2 × 0.100
            ≈ 102.02 mm

But if:

dt = 0.049 s

then:

deltaLength ≈ 1020.2 × 0.049
            ≈ 49.99 mm

Exactly as your console showed:

deltaLength=49.9896
...
deltaLength=102.02
...
deltaLength=52.03
...
deltaLength=102.02

So the physical process is:

time step varies
      │
      ▼
dt varies
      │
      ▼
centerlineSpeed × dt
      │
      ▼
deltaLength varies
      │
      ▼
wrappedLength grows by different amounts

That's perfectly okay.

3. What does wrappedLength / 6500 mean?

Yes, / means division.

We calculate:

formedFraction =
    currentWrappedLength
    / input.pipeArcLength;

For your pipe:

pipeArcLength = 6500 mm

Suppose:

wrappedLength = 3250 mm

Then:

formedFraction =
    3250 / 6500
  = 0.5

Meaning:

50% of the pipe material has been formed.

Another example:

wrappedLength = 4875 mm


4875 / 6500 = 0.75

So:

0.00 =   0%
0.25 =  25%
0.50 =  50%
0.75 =  75%
1.00 = 100%

Graphically:

0 mm                    3250 mm                    6500 mm
|==========================|--------------------------|
                            ^
                     wrappedLength


3250 / 6500
     =
    0.5
     =
    50%

We are normalizing physical length into a fraction from 0 to 1.

Your reference geometry has:

Their indices are:

0, 1, 2, 3, ... 25998, 25999, 26000

lastReferenceIndex = 26000;

6. Is targetFormedReferenceIndex the same thing as "target index"?

Yes.

When I write:

targetIndex

in the diagrams, that's just shorthand for:

targetFormedReferenceIndex

The full C++ name is better because it says exactly what it represents:

target
  │
  └── where we SHOULD be


formed
  │
  └── formed material


reference
  │
  └── index into referenceNodes


index
  │
  └── discrete node number

So:

targetFormedReferenceIndex = the reference node index that corresponds to the current total amount of formed material.

Suppose previous timestep ended here:

previousIndex = 24509

Now current wrapped length says we should be here:

targetIndex = 24917

Therefore:

24917 - 24509 = 408

We need to manufacture 408 new material segments/samples.

REFERENCE INDEX


0 -------------------------24509---------24917----------26000

Next timestep starts from 24917.

8. Why do we need Reference, Loaded, and History helixes?

This is the most important conceptual question.

They represent different things.

Reference/final helix

This answers:

What shape do I ultimately want after the pipe is released?

For example:

YELLOW


        final unloaded spring


      ╭────╮
    ╭─╯    ╰─╮
   ╭╯        ╰╮
   ╰╮        ╭╯
    ╰─╮    ╭─╯
      ╰────╯

This is essentially your desired CAD/result geometry.

Loaded helix

This answers:

What shape must the pipe have while the machine/support is still forcing it?

Because of springback:

loaded shape ≠ final shape

You already have:

targetKappa         = 0.00196003
loadedKappa         = 0.00217781
predictedFinalKappa = 0.00196003

So you're deliberately bending it more tightly while loaded, knowing that it will relax afterward.

Conceptually:

       LOADED                     RELEASED


      tighter                      larger
       radius                       radius


        ))))        unload          ))))
      ))    ))      ------>       ))    ))
      ))    ))                   ))        ))
        ))))                       ))))))
History helix

This answers a completely different question:

What has actually been manufactured so far?

At 20%:

incoming straight
------------------------●))))


                         ^
                    forming point

                     formedHistory

At 60%:

incoming
----------●))))))))))))))))))


           <----------------->
              formedHistory

At 100%:

●))))))))))))))))))))))))))))


 <--------------------------->
       complete history

It is process state.

It remembers material that has already passed through the forming point.

                   support tube

MH1.16.10 — Hermite equation

For normalized position:

u ∈ [0,1]

use:

P(u) =
    h00 P0
  + h10 M0
  + h01 P1
  + h11 M1

where:

h00 =  2u³ - 3u² + 1
h10 =    u³ - 2u² + u
h01 = -2u³ + 3u²
h11 =    u³ -   u²

And:

P0 = ACTIVE entry
P1 = ACTIVE exit


M0 = T_entry * tangentScale
M1 = T_exit  * tangentScale

For the first test:

tangentScale =
    activeLength;

    MH1.16.11 — Add local Hermite helper

Inside StretchHelixFormingProcess.cpp, anonymous namespace:

Vec3D evaluateHermitePosition(
    const Vec3D& p0,
    const Vec3D& p1,
    const Vec3D& m0,
    const Vec3D& m1,
    double u)
{
    const double u2 =
        u * u;


    const double u3 =
        u2 * u;


    const double h00 =
        2.0 * u3
        - 3.0 * u2
        + 1.0;


    const double h10 =
        u3
        - 2.0 * u2
        + u;


    const double h01 =
        -2.0 * u3
        + 3.0 * u2;


    const double h11 =
        u3
        - u2;


    return
        p0 * h00
        + m0 * h10
        + p1 * h01
        + m1 * h11;
}

MH1.16.12 — Add tangent derivative helper

For correct PipeNode.T:

Vec3D evaluateHermiteTangent(
    const Vec3D& p0,
    const Vec3D& p1,
    const Vec3D& m0,
    const Vec3D& m1,
    double u)
{
    const double u2 =
        u * u;


    const double dh00 =
        6.0 * u2
        - 6.0 * u;


    const double dh10 =
        3.0 * u2
        - 4.0 * u
        + 1.0;


    const double dh01 =
        -6.0 * u2
        + 6.0 * u;


    const double dh11 =
        3.0 * u2
        - 2.0 * u;


    return
        p0 * dh00
        + m0 * dh10
        + p1 * dh01
        + m1 * dh11;
}

Normalize the result before assigning it to a node.

MH1.17C.1 — add point-to-axis distance helper

In StretchHelixFormingProcess.cpp, near your other local helpers:

namespace
{


double distancePointToAxis(
    const Vec3D& point,
    const Vec3D& axisPoint,
    const Vec3D& axisDirection)
{
    Vec3D axis =
        axisDirection.normalized();


    if (axis.lengthSquared() < 1e-12)
        return 0.0;


    const Vec3D relative =
        point - axisPoint;


    const double axialProjection =
        dot(
            relative,
            axis
        );


    const Vec3D radialVector =
        relative
        - axis * axialProjection;


    return
        radialVector.length();
}


}

This calculates:

                    P pipe node
                    *
                   /
                  / R
                 /
----------------O---------------- support axis

It ignores position along the support axis and measures only
perpendicular distance.

double helixRadiusFromCurvatureTorsion(
    double curvature,
    double torsion)
{
    const double denominator =
        curvature * curvature
        + torsion * torsion;


    if (!std::isfinite(denominator)
        || denominator <= 1e-18)
    {
        return 0.0;
    }


    return
        curvature
        / denominator;
}




double helixRisePerRadianFromCurvatureTorsion(
    double curvature,
    double torsion)
{
    const double denominator =
        curvature * curvature
        + torsion * torsion;


    if (!std::isfinite(denominator)
        || denominator <= 1e-18)
    {
        return 0.0;
    }


    return
        torsion
        / denominator;
}

For a constant helix:

R = κ / (κ² + τ²)


b = τ / (κ² + τ²)


pitch = 2πb

MH1.19B.4 — put the calculation in one helper

I recommend adding:

to StretchHelixFormingProcess.

Then implementation:

bool StretchHelixFormingProcess::
rebuildRequiredSupportGeometry()
{
    requiredSupportOuterRadius =
        0.0;

    requiredSupportAxisFrame =
        Frame{};

    if (!std::isfinite(loadedHelixRadius)
        || loadedHelixRadius <= 0.0)
    {
        return false;
    }

    const double pipeOuterRadius =
        input.pipeSection.outerDiameter
        * 0.5;

    if (!std::isfinite(pipeOuterRadius)
        || pipeOuterRadius <= 0.0)
    {
        return false;
    }

    requiredSupportOuterRadius =
        loadedHelixRadius
        - pipeOuterRadius;

    if (!std::isfinite(requiredSupportOuterRadius)
        || requiredSupportOuterRadius <= 0.0)
    {
        return false;
    }

    Vec3D axisDirection =
        startFrame.T
            * loadedHelixTorsion
        + startFrame.B
            * loadedHelixCurvature;

    if (axisDirection.lengthSquared() < 1e-12)
        return false;

    axisDirection =
        axisDirection.normalized();

    const Vec3D loadedNormal =
        startFrame.N.normalized();

    if (loadedNormal.lengthSquared() < 1e-12)
        return false;

    const Vec3D axisPoint =
        startFrame.P
        + loadedNormal
        * loadedHelixRadius;

    requiredSupportAxisFrame.P =
        axisPoint;

    requiredSupportAxisFrame.T =
        axisDirection;

    requiredSupportAxisFrame.N =
        (
            startFrame.P
            - axisPoint
        ).normalized();

    requiredSupportAxisFrame.B =
        cross(
            requiredSupportAxisFrame.T,
            requiredSupportAxisFrame.N
        ).normalized();

    requiredSupportAxisFrame.N =
        cross(
            requiredSupportAxisFrame.B,
            requiredSupportAxisFrame.T
        ).normalized();

    return true;
}
